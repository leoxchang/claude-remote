# 云端中转（Cloud Relay）设计

**日期：** 2026-11-23
**状态：** 待评审
**关联契约：** [protocol/v1/relay-contract.md](../../../protocol/v1/relay-contract.md)（接口契约，独立交付物）

---

## 1. 背景与动机

现有方案是 App 与电脑 Agent 直连（Tailscale Serve 或局域网），手机必须与电脑网络可达，
配对二维码里携带电脑自身地址。实际使用中网络配置是最大的摩擦来源
（S06 验收即卡在 iPhone 未接入 tailnet）。

本设计新增一个云端中转服务（Relay）：App 和 Agent 都主动向云端建立出站连接，
云端负责**鉴权与转发**，从而：

- 手机与电脑无需网络可达，云端地址固定，开箱即用；
- 一个账号下可挂**多台电脑、多部手机**，手机可切换控制目标；
- 支持**多人使用**，账号之间完全隔离；账号仅由管理员内部添加，不开放外部注册。

## 2. 目标 / 非目标 / 反目标

**目标**

1. 云端鉴权（内部账号）+ 按账号/电脑路由消息，电脑不开任何入站端口。
2. 现有全部功能经云端可用：会话、流式事件、审批、附件、语音（ASR）、断线补同步。
3. 接口契约独立成文档，App/Agent 只依赖契约，不依赖云端实现语言。
4. 直连模式（Tailscale/LAN）原样保留，云端模式为新增路径。
5. 部署无关：单个 Node 进程即可运行，本机/局域网可开发验证，将来原样搬上云服务器。

**非目标（本期不做）**

- 外部注册、找回密码、验证邮件、OAuth、短信；
- APNs/FCM 离线推送；
- 端到端加密（云端可见明文转发内容，靠 TLS + 账号隔离保护）；
- 云端水平扩展、PostgreSQL/Redis、多实例路由；
- 计费、团队 RBAC、运营后台。

**反目标（做成这样即失败）**

- 云端理解或持久化会话内容（事件事实源永远在各电脑的 SQLite）；
- 云端契约泄漏实现细节，导致换语言重写时必须读 TypeScript 源码；
- 为云端模式引入新的网络配置负担（开端口、装 VPN 等）；
- 破坏直连模式的任何现有行为。

## 3. 约束

- 尚无服务器与域名：云端地址必须是 App/Agent 的配置项；生产 TLS 由反向代理终止。
- protocol v1（消息信封、命令/事件、`afterSeq` 补同步）语义不变，云端对其透明。
- 模型密钥、豆包 ASR 密钥只存在于电脑端；云端与手机均不接触。
- iOS/Android 后台不能依赖长连保活：后台期间断连、回前台重连补同步（现有行为）。
- 多人内部使用：需要账号隔离与基本滥用防护，不需要运营级设施。

## 4. 备选方案与选择

| 方案 | 内容 | 取舍 |
|---|---|---|
| **一：自建轻量 Relay（选定）** | monorepo 新增 `apps/relay`，Fastify + ws，SQLite(WAL) 存账号/设备，内存路由，单实例 | 一个进程 + 一个文件即完整云端；不可水平扩展、无推送，内部规模不痛 |
| 二：按架构文档完整形态 | PostgreSQL + Redis，多实例，预留推送 | 一步到位但提前背运维成本，与「简单」动机冲突 |
| 三：现成隧道/中间件（frp、EMQX） | 端口映射或 MQTT broker | frp 做不了账号隔离与多电脑路由；broker 仍需自写 epoch/HTTP 代答/吊销胶水，运维更重。排除 |

用户选择方案一，并追加要求：**对接接口形成独立文档，将来换语言按文档对接**。
存储层留接口边界（Port），将来换 PostgreSQL 不动业务代码。

## 5. 总体架构

```
手机 App ──WSS/HTTPS──> 云端 Relay <──WSS── 电脑 Agent × N
                          │
                    账号/设备注册表（SQLite WAL）
                    内存连接/通道表：按账号隔离，按 desktopId 路由
                    不解析 protocol v1，不落会话内容
```

核心机制：**通道拼接（channel splice）**。

- 每台电脑的 Agent 向云端建立一条出站 WSS（桌面连接）。
- 手机的每条连接（控制 `/ws`、语音 `/ws/asr`）被云端映射为桌面连接上的一个
  逻辑通道（`channel.open/data/close`），帧内容原样双向拼接。
- 握手、版本协商、心跳语义、事件广播全部端到端发生在手机与 Agent 之间；
  Agent 侧把每个通道适配成一个虚拟 socket，交给现有 `ConnectionManager` /
  `AsrGateway`，业务层零改动。
- 三个 HTTP 接口（附件上传、审批内容、run prompt）由云端封装为
  `http.request`/`http.response` 消息经桌面连接代答。

## 6. 关键决策

### 6.1 用户已定

- 云端做鉴权与转发；多人使用；账号仅内部添加；方案一；契约独立成文档。

### 6.2 设计者裁定（可在评审时推翻）

| 决策 | 选择 | 理由 |
|---|---|---|
| 登录方式 | 用户名 + 密码，管理员 CLI 建号/重置 | 内部添加，无外部依赖 |
| 会话凭证 | 登录签发每设备长效随机令牌，可吊销；沿用 `Bearer <deviceId>.<token>` | 与现有直连鉴权格式一致，App/Agent 改动最小；无刷新令牌复杂度 |
| 配对 | 云端模式**取消扫码配对**：登录即绑定账号，同账号手机可控名下所有电脑 | 二维码流程是为无账号直连设计的，账号体系下是多余摩擦 |
| desktopId | 即桌面客户端登录得到的 deviceId | 一套设备注册表，无双重身份 |
| 云端对协议的态度 | 完全透明（通道拼接），不解析 protocol v1 | 契约语言无关；协议演进不需要改云端 |
| 存储 | better-sqlite3 + WAL，Account/Device Store Port 隔离 | 与 Agent 同款；留 PostgreSQL 升级边界 |
| 口令/令牌落盘 | 口令 scrypt 加盐哈希；令牌 SHA-256 哈希存储 | 泄漏库文件不泄漏凭证 |
| 心跳 | 云端对两条物理链路 WS ping 15s / pong 超时 45s | 沿用现有连接层参数 |
| 代次 | 桌面连接 `connectionEpoch` 递增，旧连接立即失效（close 4000） | 架构文档 §7.3 防脑裂 |
| 管理界面 | Relay 主机本地 CLI，经 unix socket 与运行中的 Relay 交互（沿用 Agent admin 模式），无网络管理 API | 内部运维最小化；吊销/禁用即时断开存活连接 |
| 部署 | 单进程，`RELAY_LISTEN`/数据目录可配；生产由反向代理终止 TLS | 部署无关 |

## 7. 各部分改动

### 7.1 新增 `apps/relay`

- Fastify + ws + better-sqlite3；按契约实现 REST 与两类 WSS 端点。
- 模块：auth（登录/令牌）、devices（注册表/吊销）、routing（连接与通道表）、
  tunnel（HTTP 代答）、admin CLI、storage（Port + SQLite 实现）。
- 校验用 zod；日志只记元数据（deviceId/channelId/type/size），不记内容。
- **黑盒契约测试套件**：只经 HTTP/WS 访问 Relay 的验收测试，作为契约的可执行
  形式；将来换语言重写云端，跑同一套测试即可验证对接。
  套件放在独立目录、只依赖契约文档与网络端点，不 import Relay 内部代码，
  保证换实现时可原样复用。

### 7.2 Agent（`apps/agent`）

- 新增 relay connector：出站 WSS 客户端，断线指数退避重连；把通道适配为
  虚拟 socket 注入现有 `ConnectionManager` 与 `AsrGateway`；HTTP 代答分发到
  现有路由处理器（携带云端已鉴权的手机 deviceId，保留租约/ASR 归属语义）。
- 云端模式下手机无需本地配对；本地 device store 不记录云端手机。
- CLI 新增 `relay login`（用户名/密码/云端地址 → 令牌落盘）与 `relay status`。
- 配置新增 relay 段（baseUrl、开关）；令牌存 SQLite；配置版本迁移沿用现有模式。
- 直连 phone-server 照常运行（仅监听 localhost），两种模式并存。

### 7.3 App（`apps/mobile`）

- 新增云端模式：设置页填云端地址 + 登录；令牌入安全存储（沿用现有机制）。
- 电脑列表页：展示名下电脑与在线状态，选择/切换控制目标；
  切换 = 以新 `desktopId` 重建连接；会话缓存按 desktopId 隔离。
- 连接层：baseUrl 指向云端，WS 升级带 `desktopId` 查询参数，
  HTTP 请求带同一参数；协议层零改动。
- 直连模式（扫码配对）原样保留，模式在设置中切换。

### 7.4 协议（`protocol/v1`）

- `relay-contract.md`：本次新增的云端接口契约（唯一对接依据）。
- 现有 events/commands schema 与 validator 不变。

## 8. 安全与滥用防护

- 生产必须 TLS（反向代理）；契约禁止 URL 携带凭证。
- 登录限流（每用户名+IP 每分钟上限）；每账号设备数上限；
  帧/请求体大小上限；慢消费者断开。
- 账号隔离在每条路由与每个通道上强制校验；吊销/禁用立即断开存活连接。
- 云端不持久化任何转发内容；错误响应不泄漏账号/设备是否存在。

## 9. 验证策略（成功标准）

1. **契约黑盒测试**全绿（鉴权、隔离、通道拼接、HTTP 代答、吊销、代次、限流）。
2. 单元/集成测试覆盖率 ≥ 80%（relay、agent connector、mobile 新增逻辑）。
3. 端到端场景（本机 Relay + 两个 Agent 实例 + 模拟器/真机）：
   - 手机不经 tailnet/局域网直连，经云端控制两台电脑并切换；
   - 断网/杀 Relay 后重连，`afterSeq` 补同步不丢事件；
   - 附件上传、审批、语音输入经云端可用；
   - 吊销手机/禁用账号后连接立即失效；跨账号访问一律拒绝；
   - 直连模式回归不受影响。

## 10. 留给实现者的空间

- 虚拟 socket 适配的具体实现（进程内适配 vs loopback）、重连退避参数；
- 数据库 schema、admin CLI 具体命令形态、mobile UI 布局与状态管理细节；
- 通道背压的具体机制（契约只规定上限与关闭码）；
- 契约测试套件的组织与运行方式。

以上均不得改变契约的线上行为；如需改变契约，先改文档再实现。
